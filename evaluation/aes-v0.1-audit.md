# Audit of v0.1, cd73beb8dc8752468d806ca9cad319195bd4af7d

| File | Decision the text helps make | Weakness and candidate change for a later release |
|---|---|---|
| SKILL.md | Sections 2–3 distinguish visible motion from inferred implementation and require comparable baselines. Sections 6–9 separate reported success from persisted data and observed results. | The mission and closing maxim motivate without changing a decision. Sections 1, 3 and 8 repeat scope preservation. Requiring an explicit gesture model or five-part rationale for every refinement can reward unnecessary machinery. Scope custom progress to interactions the native container cannot deliver. |
| native.md | Traces hosting, navigation, editor and save ownership. Effective deployment settings and guarded calls are concrete checks. | Keeping an editor “instance” alive is ambiguous in SwiftUI, where view values can be recreated. Specify observable identity, focus, selection and undo preservation. The SDK probe supports compilation of selected iOS calls only. AppKit, availability fallbacks and OS runtime behavior lack comparable evidence. |
| preservation.md | Fixture, landmark and contact/reversal timestamps make a screenshot comparison repeatable. Explicitly marking invisible contact prevents inference from becoming fact. | Pre-change capture of both endpoints can be impossible for a new interaction. Capture the existing journey and mark the new endpoint reference-only. Account for keyboard, status clock and caret changes before attributing image differences. |
| interaction.md | Stationary coordinate space, signed displacement, shared progress and stale-completion handling can prevent jumps and accidental commits. | No concrete test distinguishes cancellation during tracking from interruption during settling. The quotient assumes nonzero measured travel. Include one interrupted return and relayout example. A pan formula and spring are design options, not evidence of Apple’s implementation. |
| haptics.md | Committed event identity, threshold rearming and a failed-action check distinguish useful feedback from repeated firing. | “Simulator traces can establish event ordering” requires an observable application event; such traces cannot establish hardware delivery. Require an identified observation point. A threshold latch adds complexity when the interaction has only endpoint feedback. |
| runtime.md | Pinned destination, unique result bundles, replayed fixture and matched profiling intervals give reproducible evidence. | Runtime guidance overlaps the core and supplies no isolation strategy for existing user data or shared simulator contention. Point to project-owned resource rules. Include one example distinguishing a blocked service from a failed test. |

Prioritize observable state preservation and the native/custom decision boundary if a trial demonstrates those failures. Condense repeated process language only after measuring whether it affects intervention burden. These are editorial and technical hypotheses. No agent decision or application-quality improvement has been measured.
